# Bug 管理

## Bug 生命周期

### 新建 (New)

刚发现的缺陷，等待确认。

### 确认 (Confirmed)

确认是真实的缺陷，分配给开发人员。

### 已分配 (Assigned)

开发人员已接收并开始处理。

### 修复中 (In Progress)

开发人员正在修复。

### 已修复 (Fixed)

开发人员完成修复，等待测试验证。

### 待验证 (Pending Verification)

修复后的版本已部署，等待测试人员验证。

### 已验证 (Verified)

测试通过，缺陷已解决。

### 关闭 (Closed)

缺陷已确认解决。

### 重新打开 (Reopened)

验证时发现问题未解决，重新提交。

### 暂缓 (Deferred)

暂时不修复，留到后续版本。

### 拒绝 (Rejected)

不认为是缺陷或无法复现。

## Bug 严重程度

### P0 - 致命 (Critical)

- 系统崩溃
- 数据丢失
- 功能完全不可用

### P1 - 严重 (High)

- 核心功能无法使用
- 严重影响用户体验
- 大量用户受影响

### P2 - 一般 (Medium)

- 功能存在缺陷但有替代方案
- 影响部分用户
- UI 显示问题

### P3 - 轻微 (Low)

- 小的 UI 问题
- 文案错误
- 不影响功能使用

## Bug 优先级

### 紧急 (Urgent)

立即修复，不能等待。

### 高 (High)

在当前版本中修复。

### 中 (Medium)

在计划版本中修复。

### 低 (Low)

在后续版本中修复或暂缓。

## Bug 报告规范

### 标题

简洁描述问题，便于理解。

```
示例：登录页面输入特殊字符导致崩溃
```

### 环境信息

- 操作系统
- 浏览器版本
- 系统版本
- 屏幕分辨率

### 复现步骤

详细描述如何重现问题。

```
1. 打开登录页面
2. 在用户名输入框输入 "test@#$%"
3. 点击登录按钮
4. 系统崩溃
```

### 预期结果

描述期望的行为。

### 实际结果

描述实际发生的行为。

### 附件

- 截图
- 日志
- 视频记录
