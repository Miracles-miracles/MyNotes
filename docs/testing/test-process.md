# 测试流程

## 需求分析

在测试开始前，需要深入理解业务需求，提取测试要点。

### 关键活动

- 阅读需求文档
- 参加需求评审会议
- 与产品经理沟通确认疑问
- 识别潜在的测试风险

### 产出物

- 需求理解笔记
- 测试范围文档
- 风险评估报告

## 用例设计

根据需求编写测试用例，确保覆盖所有功能点。

### 常用方法

- 等价类划分
- 边界值分析
- 场景法
- 错误推测法

### 用例要素

| 要素 | 说明 |
|------|------|
| 用例编号 | 唯一标识 |
| 测试标题 | 简洁描述 |
| 前置条件 | 执行前的准备 |
| 测试步骤 | 详细操作步骤 |
| 预期结果 | 期望的输出 |

## 执行测试

按照测试用例执行测试，记录缺陷。

### 执行策略

- 优先级高的用例优先执行
- 冒烟测试通过后再执行完整测试
- 及时记录发现的问题

### 缺陷记录

缺陷报告应包含：
- 缺陷描述
- 复现步骤
- 预期结果 vs 实际结果
- 影响范围
- 严重程度

## 回归测试

修复后验证，确保问题已解决且未引入新问题。

### 回归范围

- 修复的缺陷相关功能
- 关联模块
- 核心功能

## 测试报告

总结测试结果，输出测试报告。

### 报告内容

- 测试执行情况
- 缺陷统计
- 测试结论
- 建议与风险
